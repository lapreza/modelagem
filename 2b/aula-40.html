Semana 10 — Aula 4

Transações e Controle de Concorrência

O que é uma Transação em SQL?

Uma Transação é uma sequência de uma ou mais instruções SQL executadas como uma única unidade lógica de trabalho. Ou todas as operações da transação são concluídas com sucesso, ou nenhuma delas é aplicada ao banco de dados.

1. As Propriedades ACID

Para garantir a integridade dos dados mesmo em caso de falhas de energia, erros de software ou acessos simultâneos, o SGBD deve cumprir quatro propriedades fundamentais:

  • Atomicidade (Atomicity): A transação é tratada como uma unidade indivisível ("tudo ou nada"). Se uma instrução falhar, todas as alterações anteriores da transação são desfeitas.
  • Consistência (Consistency): O banco de dados transita apenas de um estado válido a outro estado válido, respeitando todas as regras e restrições (constraints) do esquema.
  • Isolamento (Isolation): Transações executadas simultaneamente não devem interferir umas nas outras antes de serem finalizadas.
  • Durabilidade (Durability): Uma vez que a transação é confirmada (committed), suas alterações tornam-se permanentes e resistem a eventuais falhas do sistema.

2. Comandos de Controle de Transação (TCL)

START TRANSACTION / BEGIN TRANSACTION

Inicia um bloco de transação explícito.

COMMIT

Confirma permanentemente todas as alterações realizadas durante a transação.

ROLLBACK

Cancela e desfaz todas as alterações realizadas desde o início da transação.

SAVEPOINT

Define um ponto intermediário de restauração dentro da transação, permitindo desfaçamentos parciais.

-- Exemplo de transferência bancária entre contas (Transação Segura)
BEGIN TRANSACTION;

-- Débito da conta de origem
UPDATE contas_bancarias 
SET saldo = saldo - 500.00 
WHERE id_conta = 101;

-- Criação de um ponto de restauração
SAVEPOINT debito_realizado;

-- Crédito na conta de destino
UPDATE contas_bancarias 
SET saldo = saldo + 500.00 
WHERE id_conta = 202;

-- Se tudo estiver correto, confirma a transação
COMMIT;

-- Em caso de erro em qualquer etapa:
-- ROLLBACK; (ou ROLLBACK TO debito_realizado;)

3. Níveis de Isolamento e Concorrência

Quando múltiplos usuários acessam o banco simultaneamente, podem ocorrer problemas como Leitura Suja (Dirty Read), Leitura Não Repetível (Non-Repeatable Read) e Leitura Fantasma (Phantom Read). O SQL ANSI define 4 níveis de isolamento para controlar esses efeitos:

READ UNCOMMITTED: Permite leitura suja (menor isolamento, maior velocidade).

READ COMMITTED: Evita leitura suja; lê apenas dados já confirmados.

REPEATABLE READ: Garantia de que a releitura de uma linha trará os mesmos dados.

SERIALIZABLE: Isolamento total através de bloqueios (locks); transações são executadas sequencialmente (maior consistência, menor concorrência).

Semana 11 — Aula 2

Backup e Restauração de Dados

A Importância do Backup em Bancos de Dados

O procedimento de Backup consiste em criar cópias de segurança do esquema e dos dados armazenados no SGBD para prevenir perdas provocadas por falhas de hardware, exclusões acidentais, ataques cibernéticos ou desastres naturais.

1. Backup Lógico vs Backup Físico

Backup Lógico

Exporta a estrutura (DDL) e os registros (DML) em formato de comandos SQL legíveis (scripts .sql). É altamente portátil entre diferentes versões do SGBD, porém o processo de restauração é mais lento por exigir a reexecução de todas as instruções. 

# Exemplo de backup lógico no PostgreSQL via linha de comando (pg_dump)
pg_dump -U usuario -d escola_db > backup_escola.sql

# Exemplo no MySQL (mysqldump)
mysqldump -u usuario -p escola_db > backup_escola.sql

Backup Físico

Copia diretamente os arquivos binários de dados, tabelas e logs armazenados pelo SGBD no disco rígido. É extremamente rápido na restauração, mas exige compatibilidade estrita entre as versões e a arquitetura do servidor.

2. Estratégias de Cópia de Segurança

  • Full Backup (Completo): Copia 100% dos dados e esquemas do banco. Serve de base para qualquer plano de recuperação, mas consome mais espaço em disco e tempo de execução.
  • Backup Diferencial: Copia apenas as alterações ocorridas desde a realização do último Full Backup. É mais rápido de restaurar que o incremental.
  • Backup Incremental: Copia apenas os dados modificados desde o último backup de qualquer tipo (Full ou Incremental). Economiza espaço em disco, mas a restauração exige aplicar todos os backups incrementais na ordem cronológica exata.

3. Restauração e Métricas de Disponibilidade (RPO e RTO)

A Restauração (Restore) é o processo inverso de recriação das tabelas e carga dos dados no SGBD a partir dos arquivos de backup salvos. 

# Restaurando um backup lógico SQL no servidor PostgreSQL
psql -U usuario -d escola_db < backup_escola.sql

RPO (Recovery Point Objective): Determina o limite aceitável de perda de dados medido em tempo (ex: no máximo 1 hora de dados perdidos).

RTO (Recovery Time Objective): Determina o tempo máximo tolerado para que o banco volte a operar após uma parada crítica.

Atividade de Fixação

  1. Qual é a diferença fundamental entre um **Backup Lógico** e um **Backup Físico** em relação à velocidade de restauração e à portabilidade?
  2. Explique a diferença entre uma estratégia de **Backup Diferencial** e uma de **Backup Incremental**.
  3. O que indicam as métricas **RPO** e **RTO** no planejamento de um plano de recuperação de desastres (Disaster Recovery)?

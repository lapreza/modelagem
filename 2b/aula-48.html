Semana 12 — Aula 4

Modificação de Estruturas de Dados

Evolução de Esquemas em Sistemas em Produção

À medida que um software evolui, os requisitos de negócio mudam, exigindo que a estrutura das tabelas existentes seja ajustada sem causar perda dos dados já armazenados. O comando ALTER TABLE é a ferramenta principal da DDL para gerenciar essa evolução.

1. Adicionando e Removendo Colunas

Podemos incluir novos campos com ou sem valores padrão, bem como remover colunas obsoletas. 

-- Adicionando uma nova coluna com valor padrão (Preserva registros existentes)
ALTER TABLE alunos 
ADD COLUMN telefone VARCHAR(20) DEFAULT 'Não Informado';

-- Removendo uma coluna e seus dados associados permanentemente
ALTER TABLE alunos 
DROP COLUMN telefone;

Atenção ao Adicionar NOT NULL: Se tentar adicionar uma coluna com a restrição NOT NULL em uma tabela que já contém dados, deve fornecer obrigatoriamente um valor DEFAULT, caso contrário o SGBD rejeitará a instrução.

2. Renomeando Tabelas e Colunas

A alteração de nomes de identificadores deve ser feita com cautela, pois pode afetar consultas de aplicações, visões e procedimentos armazenados. 

-- Renomeando uma coluna na tabela (Sintaxe ANSI / PostgreSQL)
ALTER TABLE alunos 
RENAME COLUMN nome_aluno TO nome_completo;

-- Renomeando a tabela inteira
ALTER TABLE alunos 
RENAME TO estudantes;

3. Adicionando e Removendo Constraints

É possível vincular novas chaves estrangeiras ou restrições de validação a uma tabela existente. 

-- Adicionando uma Foreign Key a uma tabela já existente
ALTER TABLE matriculas
ADD CONSTRAINT fk_matriculas_alunos
FOREIGN KEY (id_aluno) REFERENCES estudantes(id_aluno)
ON DELETE CASCADE;

-- Removendo uma constraint específica pelo nome
ALTER TABLE matriculas
DROP CONSTRAINT fk_matriculas_alunos;

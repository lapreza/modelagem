Semana 14 — Aula 1

Normalização de Banco de Dados

O que é Normalização?

A Normalização é um processo formal de organização de tabelas e atributos em um banco de dados relacional com o objetivo de eliminar redundâncias de dados e evitar anomalias de inserção, atualização e exclusão.

1. Primeira Forma Normal (1FN) — Atomicidade

Uma tabela está na 1FN quando todos os seus atributos contêm apenas valores atômicos (indivisíveis), ou seja, não existem grupos repetitivos ou colunas multivaloradas (listas separadas por vírgula) em uma mesma célula. 

-- ❌ FORA DA 1FN (Coluna multivalorada 'telefones')
+----------+--------------+---------------------------+
| id_aluno | nome_aluno   | telefones                 |
+----------+--------------+---------------------------+
| 1        | Ana Silva    | (19) 9911-2233, 3873-4455 |
+----------+--------------+---------------------------+

-- ✅ APLICANDO A 1FN (Separação em tabela filha com relação 1:N)
CREATE TABLE telefones_alunos (
    id_telefone INT PRIMARY KEY,
    id_aluno INT REFERENCES alunos(id_aluno),
    numero VARCHAR(20) NOT NULL
);

2. Segunda Forma Normal (2FN) — Dependência Funcional Total

Uma tabela está na 2FN quando já atende à 1FN e todos os seus atributos não-chave dependem totalmente da chave primária inteira (elimina dependências parciais em chaves primárias compostas).

Exemplo Clássico: Em uma tabela itens_pedido (id_pedido, id_produto, nome_produto, quantidade), o atributo nome_produto depende apenas de id_produto (parte da chave composta). Para atingir a 2FN, nome_produto deve ser movido para a tabela produtos.

3. Terceira Forma Normal (3FN) — Dependência Transitiva

Uma tabela está na 3FN quando está na 2FN e nenhum atributo não-chave depende transitivamente de outro atributo não-chave. Toda coluna deve depender exclusivamente da Chave Primária ("a chave, toda a chave e nada mais que a chave"). 

-- ❌ FORA DA 3FN ('nome_cidade' depende de 'cep', que não é a PK da tabela)
CREATE TABLE alunos_nao_normalizada (
    id_aluno INT PRIMARY KEY,
    nome_aluno VARCHAR(100),
    cep VARCHAR(9),
    nome_cidade VARCHAR(80) -- Dependência transitiva via CEP!
);

-- ✅ APLICANDO A 3FN (Extraindo a entidade Endereços/CEPs)
CREATE TABLE ceps (
    cep VARCHAR(9) PRIMARY KEY,
    nome_cidade VARCHAR(80) NOT NULL
);

CREATE TABLE alunos (
    id_aluno INT PRIMARY KEY,
    nome_aluno VARCHAR(100) NOT NULL,
    cep VARCHAR(9) REFERENCES ceps(cep)
);

4. Forma Normal de Boyce-Codd (BCNF)

A BCNF é uma versão mais rigorosa da 3FN. Ela estabelece que, para toda dependência funcional não trivial $X \rightarrow Y$, o determinante $X$ deve ser obrigatoriamente uma Superchave da tabela.

Atividade de Fixação

  1. Quais são os três tipos de anomalias de manutenção de dados que o processo de normalização busca eliminar?
  2. Explique por que uma tabela com chave primária simples (apenas uma coluna) que já está na 1FN atende automaticamente à **Segunda Forma Normal (2FN)**.
  3. Identifique a violação da **3FN** na tabela funcionarios (id_func, nome, id_depto, nome_depto) e apresente a solução normalizada.

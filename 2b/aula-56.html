Semana 14 — Aula 4 (Encerramento do 2º Bimestre)

Projeto Final de Modelagem e SQL

Escopo do Projeto Integrador

Nesta aula de consolidação do 2º Bimestre, projetaremos e implementaremos de ponta a ponta o banco de dados relacional de uma **Plataforma de Gestão de Biblioteca Digital e Empréstimos**, aplicando normalização até a 3FN, criação de índices, carga transacional, gatilhos de automação e consultas analíticas.

Etapa 1: Implementação Física Normalizada (DDL e Índices)

As entidades são separadas para eliminar dependências parciais e transitivas (3FN), definindo chaves primárias, estrangeiras e índices nas colunas de busca frequente: 

CREATE TABLE categorias (
    id_categoria INT PRIMARY KEY,
    nome_categoria VARCHAR(60) NOT NULL UNIQUE
);

CREATE TABLE livros (
    id_livro INT PRIMARY KEY,
    isbn VARCHAR(17) NOT NULL UNIQUE,
    titulo VARCHAR(150) NOT NULL,
    id_categoria INT NOT NULL REFERENCES categorias(id_categoria),
    exemplares_disponiveis INT NOT NULL CHECK (exemplares_disponiveis >= 0)
);

CREATE TABLE leitores (
    id_leitor INT PRIMARY KEY,
    nome_leitor VARCHAR(100) NOT NULL,
    email VARCHAR(120) NOT NULL UNIQUE,
    status_conta VARCHAR(20) DEFAULT 'Ativo'
);

CREATE TABLE emprestimos (
    id_emprestimo INT PRIMARY KEY,
    id_livro INT NOT NULL REFERENCES livros(id_livro),
    id_leitor INT NOT NULL REFERENCES leitores(id_leitor),
    data_retirada DATE NOT NULL DEFAULT CURRENT_DATE,
    data_devolucao_prevista DATE NOT NULL,
    data_devolucao_real DATE NULL
);

-- Índices para acelerar junções e filtros por leitor/livro
CREATE INDEX idx_emprestimos_leitor ON emprestimos(id_leitor);
CREATE INDEX idx_emprestimos_livro ON emprestimos(id_livro);

Etapa 2: Carga Inicial Transacional (DML + ACID)

Utilizamos uma transação explícita para inserir os dados iniciais respeitando a hierarquia entre tabelas pai e filha: 

BEGIN TRANSACTION;

INSERT INTO categorias (id_categoria, nome_categoria) VALUES 
    (1, 'Banco de Dados'),
    (2, 'Engenharia de Software');

INSERT INTO livros (id_livro, isbn, titulo, id_categoria, exemplares_disponiveis) VALUES 
    (101, '978-85-7522-001', 'Sistemas de Banco de Dados', 1, 5),
    (102, '978-85-7522-002', 'Arquitetura Limpa', 2, 3);

INSERT INTO leitores (id_leitor, nome_leitor, email) VALUES 
    (501, 'Fernanda Lima', 'fernanda@email.com'),
    (502, 'Ricardo Alves', 'ricardo@email.com');

INSERT INTO emprestimos (id_emprestimo, id_livro, id_leitor, data_retirada, data_devolucao_prevista) VALUES 
    (9001, 101, 501, '2026-11-01', '2026-11-15'),
    (9002, 102, 502, '2026-11-05', '2026-11-19');

COMMIT;

Etapa 3: Automação de Estoque com Trigger

Sempre que um novo empréstimo for registrado, o saldo de exemplares disponíveis na tabela livros deve ser reduzido automaticamente: 

DELIMITER //
CREATE TRIGGER trg_BaixaExemplarEmprestimo
AFTER INSERT ON emprestimos
FOR EACH ROW
BEGIN
    UPDATE livros
    SET exemplares_disponiveis = exemplares_disponiveis - 1
    WHERE id_livro = NEW.id_livro;
END //
DELIMITER ;

Etapa 4: Relatórios Analíticos e View Gerencial

Por fim, encapsulamos uma consulta com INNER JOIN, agregação e filtro HAVING em uma VIEW para monitorar empréstimos em aberto: 

CREATE VIEW vw_emprestimos_ativos AS
SELECT 
    l.nome_leitor,
    lv.titulo AS livro_emprestado,
    c.nome_categoria,
    e.data_retirada,
    e.data_devolucao_prevista
FROM emprestimos e
INNER JOIN leitores l ON e.id_leitor = l.id_leitor
INNER JOIN livros lv ON e.id_livro = lv.id_livro
INNER JOIN categorias c ON lv.id_categoria = c.id_categoria
WHERE e.data_devolucao_real IS NULL;

-- Consultando empréstimos vencidos
SELECT * FROM vw_emprestimos_ativos 
WHERE data_devolucao_prevista < CURRENT_DATE;

Aula 57: Introdução aos SGBDs Relacionais

Compreenda a arquitetura, o funcionamento e o papel essencial dos Sistemas Gerenciadores de Banco de Dados (SGBDs) relacionais no armazenamento estruturado, seguro e íntegro das informações.

1. O que é um SGBD Relacional?

Um Sistema Gerenciador de Banco de Dados (SGBD) é o software responsável por criar, organizar, armazenar, proteger e permitir o acesso aos dados de forma estruturada. Ele atua como uma camada intermediária entre as aplicações (sites, sistemas empresariais, aplicativos mobile) e os arquivos físicos gravados no disco.

Quando falamos de um SGBD Relacional (SGBDR) — baseado no modelo proposto por Edgar F. Codd em 1970 —, os dados são organizados em tabelas (relações) compostas por linhas e colunas, conectadas entre si por meio de chaves.

Conceito-Chave: O Banco de Dados é o conjunto organizado de informações armazenadas; o SGBD é o motor de software que gerencia esse acervo (como MySQL, PostgreSQL, Oracle, SQL Server e SQLite).

2. Estrutura Básica do Modelo Relacional

Para entender como um SGBDR opera internamente, é fundamental dominar a terminologia técnica que conecta a teoria matemática à prática do desenvolvimento:

  • Tabela (Relação): Representa uma entidade do mundo real (ex.: alunos, cursos, matriculas).
  • Coluna (Atributo): Define uma característica específica e o tipo de dado aceito (ex.: nome VARCHAR(100), data_nascimento DATE).
  • Linha (Tupla ou Registro): Representa uma ocorrência individual dentro da tabela (ex.: os dados completos de um único aluno).
  • Domínio: Conjunto de valores válidos permitidos para uma determinada coluna (ex.: notas entre 0.0 e 10.0).
  • Chave Primária (PK) e Estrangeira (FK): Mecanismos que garantem a unicidade de cada registro e estabelecem os vínculos entre tabelas distintas.
-- Exemplo prático de estrutura relacional entre duas tabelas
CREATE TABLE cursos (
    id_curso INT PRIMARY KEY,
    nome_curso VARCHAR(80) NOT NULL
);

CREATE TABLE alunos (
    id_aluno INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    id_curso INT,
    FOREIGN KEY (id_curso) REFERENCES cursos(id_curso)
);

3. Principais Responsabilidades de um SGBDR

Diferente de salvar dados em planilhas ou arquivos de texto simples, um SGBD relacional oferece recursos avançados indispensáveis para sistemas profissionais:

  1. Integridade dos Dados: Impede inconsistências (como cadastrar uma matrícula para um aluno inexistente) por meio de restrições (constraints).
  2. Controle de Concorrência: Permite que centenas ou milhares de usuários leiam e alterem dados simultaneamente sem corromper as informações.
  3. Segurança e Controle de Acesso: Gerencia usuários, senhas e permissões granulares (quem pode ler, inserir, alterar ou apagar cada tabela).
  4. Backup e Recuperação (Recovery): Mantém logs de transações que permitem restaurar o banco ao estado consistente após falhas de energia ou hardware.
  5. Independência de Dados: Permite alterar a forma como os arquivos são gravados fisicamente sem quebrar o código SQL das aplicações.

4. Panorama dos Principais SGBDs Relacionais

Na prática profissional, a escolha do SGBDR depende do porte do projeto, orçamento e requisitos de escalabilidade:

SGBD Licença Características Principais Cenário Comum de Uso
MySQL / MariaDB Open Source / Comercial Leve, rápido, amplamente suportado em hospedagens e muito popular na web. Aplicações Web, e-commerce, sistemas PHP/Node/Python.
PostgreSQL Open Source (PostgreSQL) Extremamente robusto, aderente ao padrão SQL, suporta JSON e dados geoespaciais. Sistemas corporativos complexos, análise de dados, fintechs.
SQL Server Proprietária (Microsoft) Forte integração com o ecossistema Windows, .NET e ferramentas de BI (Power BI). Empresas que utilizam infraestrutura Microsoft.
Oracle Database Proprietária (Oracle) Altíssima performance, escalabilidade massiva e recursos avançados de alta disponibilidade. Bancos, telecomunicações e grandes corporações.
SQLite Domínio Público Embarcado (sem servidor), armazenado em um único arquivo local. Aplicativos Mobile (Android/iOS), protótipos e sistemas desktop.

5. Exercícios de Fixação

Teste sua compreensão sobre os fundamentos dos SGBDs relacionais antes de avançar para a próxima aula:

1. Qual é a diferença fundamental entre um Banco de Dados e um SGBD?

Ver resposta comentada
O Banco de Dados é o acervo organizado de dados propriamente dito (as tabelas e registros armazenados), enquanto o SGBD (como MySQL ou PostgreSQL) é o software responsável por gerenciar, proteger, consultar e manter a integridade desse acervo.

2. No modelo relacional, como são chamados formalmente a tabela, a linha e a coluna?

Ver resposta comentada
Respectivamente: Relação (tabela), Tupla (linha/registro) e Atributo (coluna/campo).

3. Por que o SQLite é amplamente utilizado em desenvolvimento Mobile em comparação ao Oracle Database?

Ver resposta comentada
Porque o SQLite é um SGBD embarcado que não exige um processo de servidor separado — todo o banco fica em um único arquivo leve dentro do próprio smartphone, consumindo pouquíssima memória e processamento.

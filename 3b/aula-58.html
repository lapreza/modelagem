Aula 58: Modelagem de Dados Relacional

Aprenda a transformar requisitos de negócio e diagramas conceituais (MER/DER) em esquemas lógicos relacionais bem estruturados, aplicando regras de mapeamento de entidades, atributos e cardinalidades.

1. Os Três Níveis da Modelagem de Dados

Construir um banco de dados relacional eficiente exige planejar antes de escrever código SQL. Esse processo é dividido em três etapas progressivas que vão do negócio até a implementação no SGBD:

  • Modelo Conceitual (MER / DER): Foca nas regras de negócio, identificando entidades, atributos e relacionamentos sem se preocupar com o SGBD escolhido.
  • Modelo Lógico Relacional: Traduz o modelo conceitual para tabelas, colunas, chaves primárias (PK), chaves estrangeiras (FK) e tipos abstratos de dados.
  • Modelo Físico: Adapta o esquema lógico para um SGBD específico (MySQL, PostgreSQL, etc.), definindo tipos exatos (INT, VARCHAR, DECIMAL), índices, constraints e regras de armazenamento.
Boas Práticas: Um erro detectado na fase de modelagem lógica custa minutos para ser corrigido. O mesmo erro descoberto após o sistema entrar em produção exige migrações complexas e arriscadas.

2. Regras de Mapeamento (Do DER para Tabelas)

Para converter um Diagrama Entidade-Relacionamento (DER) em um projeto lógico relacional consistente, aplicamos regras objetivas conforme a cardinalidade dos relacionamentos:

Elemento no DER Conversão no Modelo Relacional Exemplo Prático
Entidade Forte Torna-se uma tabela própria; o atributo identificador vira a Chave Primária (PK). Entidade Cliente → Tabela clientes(id_cliente PK, nome, cpf).
Relacionamento 1 : 1 A PK de uma tabela é inserida como FK (com restrição UNIQUE) na outra, ou ambas são fundidas. Funcionario (1) — (1) Cracha → crachas(..., id_funcionario FK UNIQUE).
Relacionamento 1 : N A PK do lado 1 migra como Chave Estrangeira (FK) para a tabela do lado N. Departamento (1) — (N) Funcionario → funcionarios(..., id_departamento FK).
Relacionamento N : M Cria-se uma tabela associativa contendo as PKs de ambas as tabelas como FKs (formando PK composta). Aluno (N) — (M) Disciplina → Tabela matriculas(id_aluno FK, id_disciplina FK, nota).
Atributo Multivalorado Torna-se uma nova tabela vinculada à tabela principal por FK. Vários telefones por cliente → Tabela telefones_cliente(id_telefone PK, id_cliente FK, numero).

3. Exemplo Prático: Sistema de Biblioteca

Considere o seguinte cenário: um Leitor pode realizar vários Empréstimos (1:N), e cada empréstimo pode conter vários Livros (N:M). Veja como fica a representação textual do esquema lógico relacional:

-- Representação Textual do Modelo Lógico Relacional
leitores (id_leitor PK, nome, email, telefone)
livros (id_livro PK, titulo, autor, isbn, ano_publicacao)
emprestimos (id_emprestimo PK, data_retirada, data_devolucao, id_leitor FK)
itens_emprestimo (id_emprestimo PK/FK, id_livro PK/FK, observacao)

Implementação Física em SQL

CREATE TABLE leitores (
    id_leitor INT PRIMARY KEY AUTO_INCREMENT,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(120) UNIQUE NOT NULL
);

CREATE TABLE livros (
    id_livro INT PRIMARY KEY AUTO_INCREMENT,
    titulo VARCHAR(150) NOT NULL,
    isbn VARCHAR(20) UNIQUE
);

CREATE TABLE emprestimos (
    id_emprestimo INT PRIMARY KEY AUTO_INCREMENT,
    data_retirada DATE NOT NULL,
    id_leitor INT NOT NULL,
    FOREIGN KEY (id_leitor) REFERENCES leitores(id_leitor)
);

CREATE TABLE itens_emprestimo (
    id_emprestimo INT,
    id_livro INT,
    PRIMARY KEY (id_emprestimo, id_livro),
    FOREIGN KEY (id_emprestimo) REFERENCES emprestimos(id_emprestimo),
    FOREIGN KEY (id_livro) REFERENCES livros(id_livro)
);

4. Restrições de Integridade no Modelo Relacional

Um bom modelo relacional protege a qualidade dos dados por meio de três pilares fundamentais de integridade:

  1. Integridade de Domínio: Garante que cada coluna receba apenas valores compatíveis com seu tipo e regra (ex.: CHECK (salario > 0), NOT NULL).
  2. Integridade de Entidade: Determina que nenhuma chave primária pode ser nula (NULL) nem repetida, garantindo identificação única para cada linha.
  3. Integridade Referencial: Assegura que todo valor preenchido em uma Chave Estrangeira (FK) corresponda obrigatoriamente a uma Chave Primária (PK) existente na tabela referenciada.

5. Exercícios de Fixação

Resolva os cenários abaixo para consolidar as regras de modelagem relacional:

1. Em um relacionamento 1:N entre Medico (1) e Consulta (N), qual tabela deve receber a Chave Estrangeira (FK)?

Ver resposta comentada
A tabela consultas (lado N) deve receber a coluna id_medico como Chave Estrangeira, pois cada consulta pertence a um único médico, enquanto um médico realiza várias consultas.

2. Por que não podemos resolver um relacionamento N:M (como Produto e Pedido) colocando apenas uma FK em cada tabela?

Ver resposta comentada
Porque uma coluna simples armazena apenas um valor atômico por linha. Se um pedido tiver 5 produtos diferentes, seria impossível guardar 5 IDs na mesma célula sem violar a estrutura relacional. Por isso criamos uma tabela associativa (ex.: itens_pedido).

3. O que ocorre se tentarmos inserir na tabela emprestimos um id_leitor = 999 quando esse código não existe na tabela leitores?

Ver resposta comentada
O SGBD bloqueia a operação imediatamente e retorna um erro de violação de Integridade Referencial, impedindo a criação de registros "órfãos".

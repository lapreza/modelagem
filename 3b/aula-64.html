Aula 64: Vistas (Views) em Bancos de Dados Relacionais

Aprenda a criar tabelas virtuais (Views) para encapsular consultas complexas, simplificar relatórios, aumentar a segurança de acesso às colunas sensíveis e distinguir Views tradicionais de Materialized Views.

1. O que são Vistas (Views)?

Uma View (Vista) é uma tabela virtual cujo conteúdo é definido por uma consulta SELECT armazenada no catálogo do SGBD. Diferente de uma tabela física comum, uma View tradicional não armazena dados próprios em disco — sempre que você consulta a View, o SGBD executa dinamicamente a query subjacente sobre as tabelas reais.

Principais Vantagens do Uso de Views

  • Abstração e Simplicidade: Encapsula consultas complexas com múltiplos JOINs e cálculos em um objeto simples, permitindo que desenvolvedores façam apenas SELECT * FROM vw_relatorio_vendas.
  • Segurança e Controle de Acesso: Permite expor apenas colunas específicas para determinados perfis de usuários, ocultando campos sensíveis (como salario, senha_hash ou cpf) sem dar acesso direto às tabelas originais.
  • Independência Lógica: Se a estrutura interna das tabelas mudar durante uma refatoração, basta atualizar a definição da View para que os sistemas externos continuem funcionando sem quebrar.
Convenção de Nomenclatura: É uma boa prática prefixar o nome das vistas com vw_ (ex.: vw_clientes_ativos) para diferenciá-las imediatamente das tabelas físicas durante a escrita de consultas.

2. Sintaxe SQL: CREATE, ALTER/REPLACE e DROP VIEW

Veja como criar uma View que consolida dados de pedidos e clientes, ocultando colunas confidenciais:

-- Criando ou substituindo uma View
CREATE OR REPLACE VIEW vw_resumo_pedidos AS
SELECT 
    p.id_pedido,
    p.data_pedido,
    c.nome AS nome_cliente,
    c.cidade,
    p.valor_total
FROM pedidos p
INNER JOIN clientes c ON p.id_cliente = c.id_cliente
WHERE p.status = 'CONCLUIDO';

-- Consultando a View exatamente como uma tabela normal
SELECT nome_cliente, valor_total
FROM vw_resumo_pedidos
WHERE cidade = 'Sumaré';

-- Excluindo uma View (não apaga os dados das tabelas originais!)
DROP VIEW IF EXISTS vw_resumo_pedidos;

3. View Tradicional vs. Materialized View (Vista Materializada)

Em cenários de Business Intelligence (BI) e Big Data, rodar consultas pesadas toda vez que um painel é aberto pode sobrecarregar o servidor. Para esses casos, SGBDs como PostgreSQL e Oracle oferecem as Vistas Materializadas:

Característica View Tradicional (Virtual) Materialized View (Materializada)
Armazenamento Armazena apenas o código SQL da consulta; não ocupa espaço de dados. Grava fisicamente o resultado da consulta em disco, como um cache persistente.
Atualização dos Dados Sempre 100% em tempo real, pois lê direto das tabelas base a cada acesso. Precisa ser atualizada manualmente ou via agendamento (REFRESH MATERIALIZED VIEW).
Desempenho de Leitura Depende do custo da consulta original toda vez que é chamada. Extremamente rápida para consultas analíticas pesadas e agregações complexas.
Atenção sobre Atualizações via View: Embora seja possível executar UPDATE ou INSERT através de Views muito simples (baseadas em uma única tabela sem agregações), Views que contêm JOIN, GROUP BY, DISTINCT ou funções de agregação são somente leitura.

4. Exercícios de Fixação

Verifique sua compreensão sobre o funcionamento e as aplicações de Views:

1. Se um administrador executar o comando DROP VIEW vw_funcionarios_publicos;, os registros dos funcionários serão apagados da tabela física funcionarios?

Ver resposta comentada
Não. Uma View tradicional é apenas uma definição de consulta salva no banco. Excluir a View remove somente a definição virtual, mantendo todos os dados intactos nas tabelas físicas de origem.

2. Como uma View pode ajudar a cumprir requisitos de privacidade (como a LGPD) em uma empresa onde estagiários precisam gerar relatórios de vendas, mas não podem ver o CPF nem o telefone dos clientes?

Ver resposta comentada
Cria-se uma View (ex.: vw_vendas_anonimizadas) selecionando apenas o ID do pedido, nome do cliente, cidade e valor da compra, omitindo as colunas cpf e telefone. Em seguida, concede-se permissão SELECT aos estagiários apenas na View, revogando o acesso direto à tabela clientes.

3. Em qual situação vale mais a pena utilizar uma Materialized View em vez de uma View comum?

Ver resposta comentada
Quando você possui um relatório gerencial pesado que cruza milhões de linhas com vários JOINs e agrupamentos (SUM, COUNT), consultado dezenas de vezes por minuto, e os dados não precisam refletir alterações do último segundo (ex.: fechamento diário ou horário).

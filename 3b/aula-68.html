Aula 68: Subconsultas e Consultas Aninhadas

Aprenda a escrever consultas dentro de outras consultas (Subqueries) nas cláusulas WHERE, FROM e SELECT, utilizando operadores escalares, IN, EXISTS, ANY e ALL, além da diferença entre subconsultas independentes e correlacionadas.

1. O que são Subconsultas (Subqueries)?

Uma Subconsulta (ou consulta aninhada) é uma instrução SELECT escrita dentro de outra instrução SQL (como outro SELECT, INSERT, UPDATE ou DELETE), sempre delimitada por parênteses ( ... ).

Elas resolvem problemas em duas etapas de forma natural: primeiro calculam um valor ou conjunto intermediário (ex.: "qual é o preço médio dos produtos?") e, em seguida, usam esse resultado para filtrar ou compor a consulta principal ("quais produtos custam acima dessa média?").

Posição da Subconsulta Retorno Esperado Aplicação Prática
Na cláusula WHERE (Escalar) 1 única linha e 1 única coluna. Comparações com =, >, <, >=, <=.
Na cláusula WHERE (Lista) Múltiplas linhas e 1 coluna. Operadores IN, NOT IN, ANY, ALL.
Na cláusula FROM (Tabela Derivada) Uma tabela temporária virtual. Aplicar uma segunda agregação sobre dados já agrupados (ex.: média dos totais por cliente).
Na cláusula SELECT (Coluna Calculada) 1 único valor escalar por linha. Exibir o total geral ao lado de cada item para cálculo de participação percentual.

2. Subconsultas no WHERE, FROM e SELECT

-- 1. Subconsulta Escalar no WHERE: produtos acima da média de preço
SELECT nome, preco
FROM produtos
WHERE preco > (SELECT AVG(preco) FROM produtos);

-- 2. Subconsulta de Lista com IN: clientes que fizeram pedidos acima de R$ 1.000
SELECT nome, email
FROM clientes
WHERE id_cliente IN (
    SELECT DISTINCT id_cliente
    FROM pedidos
    WHERE valor_total > 1000.00
);

-- 3. Tabela Derivada no FROM: média do total gasto por cliente
SELECT ROUND(AVG(total_cliente), 2) AS ticket_medio_por_cliente
FROM (
    SELECT id_cliente, SUM(valor_total) AS total_cliente
    FROM pedidos
    GROUP BY id_cliente
) AS resumo_clientes;
Atenção no FROM: Toda tabela derivada (subconsulta dentro do FROM) precisa receber um apelido (como AS resumo_clientes), caso contrário o SGBD rejeita a sintaxe.

3. Subconsultas Correlacionadas e o Operador EXISTS

Enquanto uma subconsulta comum é executada apenas uma vez antes da consulta externa, uma subconsulta correlacionada referencia uma coluna da tabela externa e, por isso, é reavaliada para cada linha candidata.

O operador EXISTS (e NOT EXISTS) verifica apenas se a subconsulta retorna pelo menos uma linha (verdadeiro/falso), interrompendo a busca assim que encontra a primeira correspondência — o que o torna extremamente rápido e imune a valores NULL:

-- Listar clientes que possuem pelo menos um pedido cancelado (EXISTS)
SELECT c.id_cliente, c.nome
FROM clientes c
WHERE EXISTS (
    SELECT 1
    FROM pedidos p
    WHERE p.id_cliente = c.id_cliente
      AND p.status = 'CANCELADO'
);
Armadilha do NOT IN com NULL: Se uma subconsulta usada com NOT IN (SELECT col FROM ...) retornar um único valor NULL na lista, toda a condição NOT IN resultará em UNKNOWN e a consulta externa retornará zero linhas! Para negações seguras, prefira sempre NOT EXISTS ou LEFT JOIN ... WHERE ... IS NULL.

4. Exercícios de Fixação

Teste seu entendimento sobre subconsultas e operadores aninhados:

1. O que acontece se executarmos SELECT nome FROM produtos WHERE preco = (SELECT preco FROM produtos WHERE categoria = 'Eletrônicos'); e houver 15 produtos na categoria Eletrônicos?

Ver resposta comentada
O SGBD emitirá um erro de execução (Subquery returns more than 1 row). O operador de igualdade simples = exige uma subconsulta escalar (apenas 1 linha e 1 coluna). Para comparar contra múltiplas linhas, deve-se usar IN (ou = ANY).

2. Por que NOT EXISTS é geralmente preferido em relação a NOT IN quando filtramos registros que não possuem correspondência em outra tabela?

Ver resposta comentada
Por dois motivos principais: (1) Segurança contra NULL — se a subconsulta do NOT IN contiver qualquer NULL, o resultado inteiro da consulta externa fica vazio; (2) Desempenho — o EXISTS/NOT EXISTS faz avaliação de curto-circuito, parando na primeira linha encontrada sem precisar materializar toda a lista.

3. Escreva uma consulta usando subconsulta escalar para exibir o nome e o salário do(s) funcionário(s) que ganham o maior salário da empresa.

Ver resposta comentada
SELECT nome, salario FROM funcionarios WHERE salario = (SELECT MAX(salario) FROM funcionarios);
(Vantagem sobre ORDER BY salario DESC LIMIT 1: se houver empate no maior salário, a subconsulta retorna todos os empatados!).

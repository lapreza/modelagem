Aula 70: Common Table Expressions (CTE)

Aprenda a estruturar consultas SQL complexas de forma modular, legível e reutilizável utilizando a cláusula WITH (Common Table Expressions), encadeamento de múltiplas CTEs e CTEs Recursivas para dados hierárquicos.

1. O que são Common Table Expressions (CTEs)?

Uma Common Table Expression (CTE) é um conjunto de resultados temporário e nomeado, definido por meio da cláusula WITH no início de uma consulta SQL. Ela existe apenas durante a execução daquela instrução (diferente de uma View, que fica salva permanentemente no catálogo do banco).

As CTEs surgiram para substituir subconsultas profundamente aninhadas no FROM, permitindo escrever a lógica de cima para baixo, em etapas claras e fáceis de dar manutenção.

Recurso Subconsulta no FROM CTE (Cláusula WITH) View (CREATE VIEW)
Persistência Apenas na consulta atual. Apenas na consulta atual. Salva permanentemente no banco.
Reutilização na mesma Query Precisa duplicar o código se usada 2 vezes. Pode ser referenciada várias vezes pelo nome. Pode ser usada em qualquer consulta futura.
Suporte a Recursão Não suporta. Suporta via WITH RECURSIVE. Não suporta diretamente (exceto via CTE interna).

2. Encadeando CTEs e Filtrando Window Functions

Você pode definir múltiplas CTEs separadas por vírgula dentro de um único bloco WITH, onde cada CTE pode ler os resultados da CTE anterior. Isso também resolve o problema clássico da Aula 69: filtrar o resultado de uma Window Function.

-- Exemplo 1: Encadeando 2 CTEs para analisar clientes acima da média
WITH vendas_por_cliente AS (
    SELECT 
        id_cliente,
        COUNT(*) AS qtd_pedidos,
        SUM(valor_total) AS total_gasto
    FROM pedidos
    WHERE status = 'CONCLUIDO'
    GROUP BY id_cliente
),
media_geral AS (
    SELECT AVG(total_gasto) AS valor_medio
    FROM vendas_por_cliente
)
SELECT 
    c.nome,
    v.qtd_pedidos,
    v.total_gasto
FROM vendas_por_cliente v
INNER JOIN clientes c ON v.id_cliente = c.id_cliente
CROSS JOIN media_geral m
WHERE v.total_gasto > m.valor_medio
ORDER BY v.total_gasto DESC;

-- Exemplo 2: Pegando apenas o produto mais caro de CADA categoria (CTE + Window Function)
WITH ranking_produtos AS (
    SELECT 
        categoria,
        nome,
        preco,
        ROW_NUMBER() OVER (PARTITION BY categoria ORDER BY preco DESC) AS rn
    FROM produtos
)
SELECT categoria, nome, preco
FROM ranking_produtos
WHERE rn = 1;

3. CTEs Recursivas (WITH RECURSIVE)

Uma CTE Recursiva referencia a si mesma para percorrer estruturas hierárquicas de profundidade desconhecida — como organogramas corporativos, árvores de categorias ou listas de materiais (Bill of Materials). Ela possui sempre duas partes unidas por UNION ALL:

  1. Membro Âncora (Base): A consulta inicial que define o ponto de partida (ex.: o diretor sem gestor, nivel = 1).
  2. Membro Recursivo: A consulta que faz JOIN com a própria CTE para buscar os subordinados do nível seguinte (nivel + 1) até não restarem mais linhas.
-- Percorrendo toda a hierarquia de cargos a partir do presidente (id_gestor IS NULL)
WITH RECURSIVE organograma AS (
    -- 1. Membro Âncora (topo da hierarquia)
    SELECT id_func, nome, id_gestor, 1 AS nivel_hierarquico
    FROM funcionarios
    WHERE id_gestor IS NULL

    UNION ALL

    -- 2. Membro Recursivo (busca subordinados diretos de cada nível)
    SELECT f.id_func, f.nome, f.id_gestor, o.nivel_hierarquico + 1
    FROM funcionarios f
    INNER JOIN organograma o ON f.id_gestor = o.id_func
)
SELECT * FROM organograma ORDER BY nivel_hierarquico, nome;
Prevenção de Loop Infinito: Se houver uma referência circular nos dados (ex.: Funcionário A é gestor de B, e B é gestor de A), uma CTE recursiva pode entrar em loop. SGBDs modernos possuem limites máximos de recursão (como MAXRECURSION no SQL Server ou cte_max_recursion_depth no MySQL) ou permitem limitar explicitamente via WHERE nivel_hierarquico < 20.

4. Exercícios de Fixação

Verifique seus conhecimentos sobre CTEs e consultas modulares:

1. Após executar uma consulta com WITH resumo_vendas AS (...) SELECT * FROM resumo_vendas;, outro desenvolvedor pode executar imediatamente SELECT * FROM resumo_vendas; em uma nova consulta separada?

Ver resposta comentada
Não. O escopo de uma CTE é estritamente limitado à única instrução SQL em que foi declarada. Assim que a consulta termina, a CTE deixa de existir. Para reutilização entre consultas distintas, deve-se criar uma View.

2. Quando definimos duas CTEs seguidas (WITH cte_a AS (...), cte_b AS (...)), a cte_b pode fazer um SELECT a partir da cte_a? E o inverso (cte_a consultar cte_b) é permitido?

Ver resposta comentada
A cte_b pode consultar a cte_a porque ela foi declarada antes. Já o inverso (cte_a consultar cte_b) não é permitido, pois a cte_b ainda não foi definida na ordem de leitura do bloco WITH.

3. Quais são os dois blocos obrigatórios dentro de uma CTE recursiva (WITH RECURSIVE)?

Ver resposta comentada
O Membro Âncora (consulta inicial não recursiva que estabelece a raiz/base) e o Membro Recursivo (consulta que referencia a própria CTE para avançar nos níveis), conectados normalmente pelo operador UNION ALL.

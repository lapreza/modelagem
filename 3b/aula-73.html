Aula 73: Diferenças entre DDL e DML

Compreenda a divisão arquitetural da linguagem SQL entre definição de estrutura (DDL) e manipulação de registros (DML), além da relação com DQL, DCL e TCL, comportamento transacional e impacto nos metadados.

1. Os Subconjuntos da Linguagem SQL

A linguagem SQL é organizada em subconjuntos funcionais de acordo com o objetivo de cada instrução sobre o banco de dados. Os dois pilares centrais da modelagem e operação são DDL e DML:

  • DDL (Data Definition Language — Linguagem de Definição de Dados): Define, altera e remove a estrutura física e lógica dos objetos do banco (tabelas, colunas, índices, views, constraints e esquemas). Atua diretamente sobre o dicionário de dados (metadados).
  • DML (Data Manipulation Language — Linguagem de Manipulação de Dados): Insere, atualiza, mescla e exclui os registros (linhas/tuplas) armazenados dentro das tabelas já existentes, sem modificar o esquema estrutural.
E onde entra o SELECT? Na literatura clássica, o comando SELECT faz parte da DML por ler dados das tabelas. Porém, na maioria das certificações e livros modernos, ele é classificado em um subconjunto próprio chamado DQL (Data Query Language), pois apenas consulta dados sem alterá-los. Completam a família a DCL (GRANT, REVOKE) e a TCL (COMMIT, ROLLBACK, SAVEPOINT).

2. Comparativo Direto: DDL vs. DML

Critério DDL (Definição de Dados) DML (Manipulação de Dados)
Alvo da Operação O esquema / estrutura (tabelas, colunas, chaves, índices). O conteúdo / registros (linhas armazenadas nas tabelas).
Comandos Principais CREATE, ALTER, DROP, TRUNCATE, RENAME INSERT, UPDATE, DELETE, MERGE (e SELECT/DQL)
Uso de Cláusula WHERE Não utiliza WHERE (atua sobre o objeto inteiro). Utiliza WHERE (exceto INSERT) para filtrar linhas específicas.
Controle Transacional (ROLLBACK) Em SGBDs como MySQL e Oracle, dispara COMMIT implícito (não pode ser desfeito). No PostgreSQL e SQL Server, é transacional. Totalmente transacional em todos os SGBDs relacionais (pode ser desfeito via ROLLBACK antes do COMMIT).
Disparo de Triggers Não dispara triggers DML de linha; exige Event/DDL Triggers específicos. Dispara triggers tradicionais (BEFORE/AFTER INSERT, UPDATE, DELETE).

3. Exemplo Lado a Lado e a Diferença entre DELETE e TRUNCATE

Observe como comandos DDL preparam o terreno estrutural para que comandos DML operem os dados do dia a dia:

-- === ETAPA 1: DDL (Definindo a estrutura no catálogo do banco) ===
CREATE TABLE departamentos (
    id_depto INT PRIMARY KEY,
    nome VARCHAR(60) NOT NULL
);

ALTER TABLE departamentos ADD COLUMN orcamento DECIMAL(12,2);

-- === ETAPA 2: DML (Manipulando os registros dentro da estrutura) ===
INSERT INTO departamentos (id_depto, nome, orcamento)
VALUES (1, 'Engenharia de Software', 150000.00);

UPDATE departamentos
SET orcamento = 180000.00
WHERE id_depto = 1;

DELETE FROM departamentos
WHERE id_depto = 1;
Por que TRUNCATE TABLE é DDL e DELETE é DML?
Embora ambos removam registros, o DELETE (DML) percorre e apaga linha por linha registrando tudo no log de transações (permitindo WHERE e ROLLBACK). Já o TRUNCATE (DDL) desaloca instantaneamente as páginas de armazenamento da tabela inteira e reinicia contadores AUTO_INCREMENT/IDENTITY, sem aceitar WHERE e sem disparar triggers de linha.

4. Exercícios de Fixação

Verifique sua compreensão sobre a classificação e o comportamento dos comandos DDL e DML:

1. Classifique cada comando abaixo como DDL ou DML: (a) ALTER TABLE clientes ADD telefone VARCHAR(20); — (b) UPDATE clientes SET telefone = '19999990000' WHERE id = 5; — (c) DROP INDEX idx_cliente_nome;

Ver resposta comentada
• (a) DDL — altera a estrutura da tabela adicionando uma coluna.
• (b) DML — modifica o dado de uma linha específica.
• (c) DDL — remove um objeto estrutural (índice) do banco de dados.

2. No MySQL, um desenvolvedor inicia uma transação (START TRANSACTION), executa um INSERT e em seguida executa um CREATE TABLE temp (id INT);. Se ele rodar ROLLBACK logo depois, o INSERT será desfeito?

Ver resposta comentada
Não! No MySQL (assim como no Oracle), qualquer comando DDL (como CREATE TABLE) provoca um COMMIT implícito antes de ser executado, consolidando permanentemente o INSERT anterior e impedindo que o ROLLBACK o desfaça.

3. Qual a diferença estrutural entre executar DROP TABLE logs_acesso; e TRUNCATE TABLE logs_acesso;?

Ver resposta comentada
O DROP TABLE apaga tanto os dados quanto a própria definição da tabela (colunas, índices e permissões deixam de existir). Já o TRUNCATE TABLE esvazia todos os registros rapidamente, mas mantém a estrutura da tabela intacta e pronta para receber novos INSERTs.

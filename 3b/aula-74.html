Aula 74: Comandos DDL Complementares

Domine recursos avançados de definição de esquema: evolução segura de tabelas com ALTER TABLE, restrições nomeadas (CHECK, UNIQUE, DEFAULT), colunas geradas, tabelas temporárias, sequências e remoção controlada com CASCADE e RESTRICT.

1. Evolução de Esquema: ALTER TABLE e Constraints Nomeadas

Em ambientes reais de produção, raramente recriamos uma tabela do zero; nós evoluímos o esquema ao longo do tempo usando subcomandos de ALTER TABLE e aplicando restrições de integridade (Constraints) diretamente no banco de dados:

  • CHECK (condição): Garante que o valor inserido ou atualizado satisfaça uma regra de negócio (ex.: preco > 0 ou nota BETWEEN 0 AND 10).
  • UNIQUE: Impede valores duplicados em uma coluna ou combinação de colunas não-primárias (ex.: CPF ou e-mail).
  • DEFAULT valor: Define um valor automático quando a coluna é omitida no INSERT.
Boas Práticas — Nomeie suas Constraints! Sempre use CONSTRAINT nome_regra (ex.: CONSTRAINT chk_estoque_positivo CHECK (estoque >= 0)). Se você não nomear, o SGBD cria códigos aleatórios como produtos_chk_1, dificultando a remoção ou alteração futura via ALTER TABLE ... DROP CONSTRAINT.

2. Recursos Estruturais Avançados em SQL

Recurso DDL Sintaxe / Comando Finalidade Prática
Alteração de Colunas e Regras ALTER TABLE ... ADD / MODIFY / RENAME / DROP Adiciona colunas, amplia tamanhos de VARCHAR, renomeia campos ou adiciona chaves e regras CHECK.
Colunas Geradas (Computed) total DECIMAL(10,2) GENERATED ALWAYS AS (qtd * preco) STORED Calcula valores automaticamente a partir de outras colunas da mesma linha (VIRTUAL calcula na leitura; STORED grava em disco).
Tabelas Temporárias CREATE TEMPORARY TABLE temp_relatorio (...) Cria uma tabela isolada da sessão atual para cálculos intermediários pesados; é destruída automaticamente ao fechar a conexão.
Sequências (Sequences) CREATE SEQUENCE seq_protocolo START WITH 1000 INCREMENT BY 1; Gera números únicos independentes de uma única tabela (útil para protocolos compartilhados entre várias tabelas).
Remoção Segura DROP TABLE IF EXISTS nome [CASCADE | RESTRICT]; IF EXISTS evita erro em scripts idempotentes; RESTRICT bloqueia se houver FKs apontando para a tabela; CASCADE remove dependências. 
-- Exemplo 1: Criando tabela com Constraints nomeadas e Coluna Gerada
CREATE TABLE IF NOT EXISTS itens_orcamento (
    id_item INT PRIMARY KEY,
    descricao VARCHAR(120) NOT NULL,
    quantidade INT NOT NULL,
    valor_unitario DECIMAL(10,2) NOT NULL,
    subtotal DECIMAL(12,2) GENERATED ALWAYS AS (quantidade * valor_unitario) STORED,
    CONSTRAINT chk_qtd_positiva CHECK (quantidade > 0),
    CONSTRAINT chk_valor_nao_negativo CHECK (valor_unitario >= 0)
);

-- Exemplo 2: Evoluindo a tabela posteriormente com ALTER TABLE
ALTER TABLE itens_orcamento
    ADD COLUMN desconto_pct DECIMAL(5,2) DEFAULT 0.00,
    ADD CONSTRAINT chk_desconto_valido CHECK (desconto_pct BETWEEN 0 AND 100);

-- Exemplo 3: Documentando metadados no catálogo com COMMENT
COMMENT ON TABLE itens_orcamento IS 'Armazena os itens detalhados de cada proposta comercial';

3. Cuidados Críticos ao Executar DDL em Produção

Bloqueio de Tabela (Table Lock) e Invalidação de Objetos:
  • Evite DROP TABLE ... CASCADE sem auditoria: Em SGBDs como PostgreSQL, o CASCADE apaga silenciosamente Views e chaves estrangeiras dependentes sem pedir confirmação.
  • Adição de colunas com DEFAULT em tabelas gigantes: Em versões antigas de alguns SGBDs, adicionar uma coluna com NOT NULL DEFAULT reescrevia toda a tabela em disco, travando leituras e escritas. SGBDs modernos otimizam isso nos metadados, mas sempre valide em homologação antes.
  • Scripts Idempotentes: Use sempre CREATE TABLE IF NOT EXISTS e DROP TABLE IF EXISTS em scripts de implantação (migrations) para evitar falhas caso o script seja executado mais de uma vez.

4. Exercícios de Fixação

Teste seus conhecimentos sobre comandos e recursos DDL complementares:

1. Qual a vantagem prática de declarar CONSTRAINT chk_idade CHECK (idade >= 18) em vez de apenas CHECK (idade >= 18) dentro de um CREATE TABLE?

Ver resposta comentada
Ao nomear explicitamente a constraint (chk_idade), você passa a ter um identificador previsível e legível tanto nas mensagens de erro quando a regra for violada quanto para removê-la ou alterá-la no futuro via ALTER TABLE ... DROP CONSTRAINT chk_idade, sem depender de nomes gerados aleatoriamente pelo SGBD.

2. Qual é a diferença entre uma coluna gerada definida como VIRTUAL e uma definida como STORED?

Ver resposta comentada
A coluna VIRTUAL não ocupa espaço físico em disco — seu valor é calculado dinamicamente toda vez que um SELECT lê a linha. Já a coluna STORED tem seu valor calculado no momento do INSERT/UPDATE e gravado fisicamente em disco como uma coluna comum (facilitando a criação de índices sobre ela).

3. O que acontece com uma TEMPORARY TABLE quando a sessão (conexão) do usuário que a criou é encerrada?

Ver resposta comentada
A tabela temporária e todos os seus dados são automaticamente destruídos pelo SGBD, além de serem invisíveis para outras conexões simultâneas durante sua existência.

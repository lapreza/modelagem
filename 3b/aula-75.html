Aula 75: Comandos DML Complementares

Domine técnicas avançadas de manipulação de dados em lote e sincronização: INSERT INTO ... SELECT, operações UPSERT (ON CONFLICT / ON DUPLICATE KEY UPDATE), comando MERGE, UPDATE e DELETE com junções e cláusula RETURNING.

1. Inserção em Lote e Operações UPSERT

Além do INSERT ... VALUES tradicional para uma ou poucas linhas, aplicações corporativas precisam copiar grandes volumes de dados entre tabelas e realizar sincronizações atômicas onde um registro deve ser inserido se não existir, ou atualizado se já existir — padrão conhecido como UPSERT (Update + Insert):

Operação / Padrão Sintaxe por SGBD Comportamento
Inserção via Consulta INSERT INTO destino (col1, col2)
SELECT c1, c2 FROM origem WHERE ...;		 Copia milhares de linhas filtradas de uma tabela (ou junção) diretamente para outra em uma única instrução.
UPSERT (PostgreSQL / SQLite) INSERT INTO ... VALUES (...)
ON CONFLICT (chave) DO UPDATE SET ...;		 Se houver violação de PRIMARY KEY ou UNIQUE, atualiza os campos desejados usando a tabela virtual EXCLUDED.
UPSERT (MySQL / MariaDB) INSERT INTO ... VALUES (...)
ON DUPLICATE KEY UPDATE col = VALUES(col);		 Executa o UPDATE automaticamente caso a chave primária ou única já exista na tabela.
MERGE (Padrão ANSI / SQL Server / Oracle / PG 15+) MERGE INTO destino USING origem ON (...)
WHEN MATCHED THEN UPDATE ...
WHEN NOT MATCHED THEN INSERT ...;		 Sincroniza uma tabela de destino completa com uma tabela de origem (staging), tratando inserções, atualizações e até exclusões.

2. Exemplos Práticos: INSERT SELECT, MERGE, UPDATE com JOIN e RETURNING

-- 1. INSERT INTO ... SELECT: arquivando pedidos concluídos de anos anteriores
INSERT INTO pedidos_historico (id_pedido, id_cliente, data_pedido, valor_total)
SELECT id_pedido, id_cliente, data_pedido, valor_total
FROM pedidos
WHERE status = 'CONCLUIDO'
  AND data_pedido < '2026-01-01';

-- 2. UPSERT (PostgreSQL): atualiza estoque se o SKU já existir
INSERT INTO produtos (sku, nome, estoque)
VALUES ('NB-DELL-15', 'Notebook Dell 15"', 12)
ON CONFLICT (sku)
DO UPDATE SET estoque = produtos.estoque + EXCLUDED.estoque;

-- 3. UPDATE com JOIN (PostgreSQL / SQL Server): reajustar preços por categoria
UPDATE produtos p
SET preco = p.preco * 1.10
FROM categorias c
WHERE p.id_categoria = c.id_categoria
  AND c.nome = 'Importados';

-- 4. Cláusula RETURNING (PostgreSQL / SQLite / MariaDB): retorna o ID gerado
INSERT INTO clientes (nome, email)
VALUES ('Mariana Costa', 'mariana@email.com')
RETURNING id_cliente, data_cadastro;
Por que usar RETURNING (ou OUTPUT no SQL Server)? Evita ter que fazer uma segunda viagem ao banco de dados (um SELECT extra) apenas para descobrir qual chave primária SERIAL/IDENTITY foi gerada no INSERT ou quais registros exatos foram afetados por um UPDATE/DELETE.

3. Cuidados em Operações DML de Lote

Atenção a Loops e Armadilhas de Sincronização:
  • Evite REPLACE INTO (MySQL) em tabelas com FKs: Diferente do ON DUPLICATE KEY UPDATE, o comando REPLACE INTO primeiro executa um DELETE físico da linha antiga e depois um INSERT novo — o que dispara triggers de exclusão e pode causar ON DELETE CASCADE indesejado em tabelas filhas!
  • Sintaxe de UPDATE com JOIN varia entre SGBDs: No MySQL escreve-se UPDATE produtos p INNER JOIN categorias c ON ... SET ...; já no PostgreSQL e SQL Server usa-se UPDATE produtos p SET ... FROM categorias c WHERE ....
  • Teste o filtro com SELECT antes: Antes de rodar um UPDATE ou DELETE complexo com junção ou subconsulta, execute um SELECT com a mesma cláusula FROM e WHERE para conferir exatamente quantas linhas serão atingidas.

4. Exercícios de Fixação

Avalie seu domínio sobre comandos DML complementares:

1. Por que o uso de ON DUPLICATE KEY UPDATE (ou ON CONFLICT DO UPDATE) é considerado mais seguro do que REPLACE INTO em tabelas que possuem chaves estrangeiras apontando para elas?

Ver resposta comentada
Porque o REPLACE INTO apaga a linha existente e insere uma nova (acionando regras ON DELETE CASCADE ou RESTRICT nas tabelas filhas), enquanto o ON DUPLICATE KEY UPDATE / ON CONFLICT DO UPDATE realiza uma atualização in-place (no próprio registro), preservando os relacionamentos existentes.

2. Qual a utilidade da cláusula RETURNING ao final de um comando DELETE ou UPDATE?

Ver resposta comentada
Ela devolve imediatamente para a aplicação as colunas (antes ou depois da modificação) das linhas que foram afetadas pelo comando DML, eliminando a necessidade de executar uma consulta SELECT adicional e garantindo consistência em ambientes concorrentes.

3. Escreva um comando DML único que copie todos os clientes com status = 'INATIVO' da tabela clientes para a tabela clientes_arquivo(id_cliente, nome, email).

Ver resposta comentada
INSERT INTO clientes_arquivo (id_cliente, nome, email)
SELECT id_cliente, nome, email FROM clientes WHERE status = 'INATIVO';

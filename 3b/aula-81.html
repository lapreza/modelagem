Aula 81: Migração de Dados

Aprenda as etapas metodológicas para migração de bases de dados relacionais: planejamento, estratégia ETL (Extract, Transform, Load), garantia de integridade referencial, mapeamento de tipos de dados e testes de homologação.

1. O Processo de Migração e Ciclo ETL

A migração de bancos de dados ocorre quando precisamos mover estruturas e dados de um SGBD para outro (ex.: de Oracle para PostgreSQL, on-premise para nuvem, ou reestruturação de schema). O processo segue a metodologia padrão ETL:

  • Extração (Extract): Coleta de dados e metadados da fonte de origem (dumps, consultas em lote ou leituras de streams de log).
  • Transformação (Transform): Limpeza, conversão de tipos de dados incompatíveis (ex.: VARCHAR2 para VARCHAR, DATETIME para TIMESTAMP WITH TIME ZONE) e ajuste de regras de negócio.
  • Carga (Load): Inserção dos dados processados no SGBD de destino, respeitando a ordem de dependência das chaves estrangeiras.
Estratégia de Janela de Manutenção: Em sistemas críticos, adota-se migração híbrida com captura de alterações em tempo real (CDC — Change Data Capture) para minimizar o tempo de indisponibilidade (downtime).

2. Mapeamento de Tipos e Cuidados com Integridade

Diferentes SGBDs implementam dialetos SQL e tipos de dados próprios. Um erro comum na migração é a perda de precisão numérica ou corrupção de caracteres especiais (problemas de Collation e codificação UTF-8).

Desafio de Migração Causa Comum Solução Recomendada
Incompatibilidade de Tipos Diferenças na representação de booleanos, datas ou números de precisão arbitrária. Criar script de mapeamento prévio de tipos de dados no DDL de destino.
Violação de Chave Estrangeira Inserção de registros filhos antes dos registros pais correspondentes. Desativar temporariamente as constraints durante a carga em lote (SET session_replication_role = 'replica';) ou ordenar o ETL adequadamente.
Divergência de Codificação Origem em Latin1/ISO-8859-1 e destino em UTF-8. Converter a codificação durante a fase de Transformação do ETL.

3. Validação e Homologação Pós-Migração

Após a execução do processo ETL, a equipe de engenharia de dados realiza auditorias rigorosas antes de liberar o sistema para produção:

  • Contagem de Linhas (Row Count Validation): Comparar o número exato de registros por tabela entre origem e destino.
  • Testes de Hash / Checksum: Validar somatórias de colunas críticas (ex.: SUM(valor_total) em pedidos) para garantir que nenhum dado foi truncado ou corrompido.
  • Validação de Aplicação: Executar baterias de testes automatizados de regressão na nova base de dados.

4. Exercícios de Fixação

1. O que significam as siglas da metodologia ETL aplicada à migração de dados?

Ver resposta comentada
Significa Extraction (Extração), Transformation (Transformação) e Load (Carga).

2. Por que a ordem das tabelas importadas é crítica ao carregar dados em um banco relacional com chaves estrangeiras ativas?

Ver resposta comentada
Porque se você tentar inserir dados em uma tabela filha antes de inserir os registros pais correspondentes na tabela referenciada, o SGBD rejeitará a operação por violação de integridade referencial.

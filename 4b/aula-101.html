Semana 26 — Aula 1

Segurança no MongoDB

Pilares da Segurança em NoSQL

Por padrão, instâncias recém-instaladas de bancos NoSQL costumam vir sem autenticação ativada para facilitar o desenvolvimento. Em ambiente de produção, é indispensável aplicar o princípio do **menor privilégio** e proteger o acesso à base através de autenticação, autorização granular e encriptação.

1. Autenticação e Mecanismo SCRAM

O MongoDB utiliza por padrão o mecanismo SCRAM (Salted Challenge Response Authentication Mechanism) (SCRAM-SHA-256) para verificar a identidade de utilizadores sem transitar senhas em texto limpo pela rede.

Ativando o Controlo de Acesso no mongod.conf:

security:
  authorization: enabled

Criando o Utilizador Administrador (no banco admin):

use admin;

db.createUser({
  user: "adminEscola",
  pwd: passwordPrompt(), // Solicita a senha de forma segura no terminal
  roles: [ { role: "userAdminAnyDatabase", db: "admin" }, "readWriteAnyDatabase" ]
});

2. Controlo de Acesso Baseado em Funções (RBAC)

O **Role-Based Access Control (RBAC)** atribui aos utilizadores apenas as permissões (funções/roles) estritamente necessárias para a realização do seu trabalho.

Funções Nativas Comuns:

  • read / readWrite: Permite leitura ou leitura/escrita em bases específicas.
  • dbAdmin: Permite tarefas administrativas (criação de índices, estatísticas da base).
  • clusterAdmin: Gestão de Replica Sets e clusters Sharded.
// Criando um utilizador limitado para a aplicação Web
use escola_db;

db.createUser({
  user: "app_user",
  pwd: passwordPrompt(),
  roles: [
    { role: "readWrite", db: "escola_db" }
  ]
});

3. Encriptação de Dados e Auditoria

Dados em Trânsito (TLS/SSL)

Garante que todo o tráfego entre a aplicação, os drivers e o cluster MongoDB seja cifrado usando certificados digitais X.509.

Dados em Repouso (Encryption at Rest)

O motor de armazenamento WiredTiger oferece cifratura nativa para arquivos de dados em disco utilizando o algoritmo AES-256.

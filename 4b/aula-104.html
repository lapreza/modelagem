Semana 26 — Aula 4

Backup e Recuperação no Apache Cassandra

Mecanismo de Escrita em Disco no Cassandra

Para compreender o backup no Cassandra, é preciso lembrar como o banco grava dados: as alterações são gravadas sequencialmente no CommitLog em disco e na memória (Memtable). Quando a Memtable fica cheia, o Cassandra realiza o *flush* e grava os dados em arquivos imutáveis no disco chamados SSTables (Sorted String Tables).

1. Snapshots com a ferramenta `nodetool`

O nodetool snapshot é a ferramenta nativa de linha de comando para criar backups físicos instantâneos de um nó.

Ao executar o comando, o Cassandra força o *flush* das Memtables para criar os arquivos SSTable atualizados e gera *hard links* (links físicos) desses arquivos dentro de um diretório de backup (`snapshots`), garantindo cópia instantânea sem consumir espaço extra de imediato. 

# Tirando um Snapshot completo do Keyspace 'escola_log' em um nó
nodetool snapshot -t backup_semanal_01 escola_log

# Onde os arquivos ficam gravados:
# /var/lib/cassandra/data/escola_log/sensores-/snapshots/backup_semanal_01/

# Limpando os arquivos de snapshot criados para liberar espaço
nodetool clearsnapshot -t backup_semanal_01 escola_log

2. Backups Incrementais (Incremental Backups)

Ao ativar a opção incremental_backups: true no cassandra.yaml, o Cassandra cria automaticamente um *hard link* de cada nova SSTable gerada após o *flush* da memória.

Estratégia Recomendada: Realizar um nodetool snapshot completo periodicamente (ex.: semanalmente) e utilizar os Incremental Backups diários para capturar apenas os deltas gravados no intervalo.

3. Restauração de Dados (Restoration e `sstableloader`)

Para restaurar um backup no Cassandra, os arquivos SSTable salvos no snapshot devem ser recolocados no nó de destino:

  • Restauração em Nó Único: Para-se o nó Cassandra, copia-se os arquivos SSTable do snapshot para o diretório de dados da tabela correspondente e reinicia-se o serviço.
  • Restauração em Cluster Ativo (`sstableloader`): A utilidade sstableloader lê os arquivos SSTable de backup e transmite (stream) as linhas via protocolo interno diretamente para os nós corretos do anel de acordo com a chave de partição.
# Carregando arquivos SSTables de backup em um cluster em execução
sstableloader -d 192.168.1.10 /backups/escola_log/sensores/

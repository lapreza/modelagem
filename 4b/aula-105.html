Semana 27 — Aula 1

Monitoramento de Performance no MongoDB

A Importância do Monitoramento em Tempo Real

Identificar gargalos de I/O, consumo excessivo de memória RAM ou consultas mal otimizadas antes que causem lentidão para o usuário final é o objetivo central do monitoramento continuo num ambiente de banco de dados NoSQL.

1. Ferramentas Utilitárias CLI (`mongostat` e `mongotop`)

mongostat

Exibe uma visão em tempo real do volume de operações por segundo (inserts, queries, updates, deletes), uso de conexões ativas, conexões pendentes e uso de memória da instância. 

# Monitorando estatísticas atualizadas a cada 1 segundo
mongostat --uri="mongodb://adminEscola:senha@localhost:27017" 1

mongotop

Acompanha o tempo acumulado que a instância mongod gasta realizando operações de leitura e escrita em cada coleção individualmente. 

# Verificando as coleções com maior tempo de I/O
mongotop --uri="mongodb://adminEscola:senha@localhost:27017" 2

2. Diagnóstico no Shell (`serverStatus` e `dbStats`)

No mongosh, comandos administrativos ajudam a inspecionar a saúde do banco: 

// Resumo geral da instância (operações de rede, cache WiredTiger, conexões)
db.serverStatus();

// Estatísticas de tamanho de armazenamento e índices do banco atual
db.stats();

// Estatísticas detalhadas de uma coleção específica
db.alunos.stats();

3. Identificando Consultas Lentas com o Database Profiler

O Database Profiler captura detalhes sobre operações de banco de dados executadas no servidor, gravando esses eventos na coleção especial system.profile.

Níveis de Profiling:

  • 0: Desativado (padrão).
  • 1: Captura apenas operações lentas (superiores ao limite definido por slowms).
  • 2: Captura todas as operações (usado apenas em diagnósticos pontuais devido ao overhead).
// Ativando o profiler para capturar consultas que demorem mais de 100ms
db.setProfilingLevel(1, { slowms: 100 });

// Consultando as 5 operações mais lentas registradas no profiler
db.system.profile.find().sort({ millis: -1 }).limit(5);

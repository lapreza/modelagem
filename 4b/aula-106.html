Semana 27 — Aula 2

Otimização de Consultas no MongoDB

O Papel dos Índices na Performance

Sem índices, o MongoDB precisa realizar uma varredura completa na coleção (COLLSCAN - Collection Scan) para encontrar os documentos que satisfazem uma consulta. Em coleções com milhões de registros, os índices estruturam os dados numa árvore **B-Tree**, reduzindo drasticamente o número de documentos inspecionados (IXSCAN - Index Scan).

1. Tipos de Índices no MongoDB

Índice Simples (Single Field Index)

Indexa um único campo em ordem ascendente (1) ou descendente (-1).

// Criando um índice simples no campo 'email'
db.alunos.createIndex({ email: 1 }, { unique: true });

Índice Composto (Compound Index)

Indexa múltiplos campos. A ordem dos campos no índice é crucial e deve seguir a regra **ESR (Equality, Sort, Range)**.

// Criando um índice composto por 'curso' (igualdade) e 'idade' (ordenação)
db.alunos.createIndex({ curso: 1, idade: -1 });

Índice Multikey (Para Arrays)

Se o campo indexado contiver um array, o MongoDB cria automaticamente um elemento de índice separado para cada item do array.

// Criando um índice no array de 'tags' de produtos
db.produtos.createIndex({ tags: 1 });

2. Analisando o Plano de Execução com `explain()`

O método explain("executionStats") permite inspecionar como a consulta foi processada pelo otimizador do MongoDB. 

// Executando a análise da consulta
db.alunos.find({ curso: "Informática" }).sort({ idade: -1 }).explain("executionStats");

Métricas Chave de Desempenho no `explain()`:

stage: IXSCAN indica uso de índice (bom); COLLSCAN indica busca total sem índice (ruim).

nReturned: Número de documentos retornados à aplicação.

totalDocsExamined: Quantidade de documentos lidos do disco/memória (quanto mais próximo de nReturned, melhor).

3. Consultas Cobertas (Covered Queries)

Uma Covered Query é a consulta com melhor desempenho possível no MongoDB. Ocorre quando:

  • Todos os campos usados no filtro de busca fazem parte de um índice.
  • Todos os campos projetados no retorno estão presentes nesse mesmo índice.
  • O campo _id é omitido da projeção (caso não faça parte do índice).

Nesse cenário, o MongoDB atende a requisição **lendo apenas o índice em memória RAM**, sem precisar acessar os documentos em disco.

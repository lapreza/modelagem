Semana 27 — Aula 4

Otimização de Consultas no Apache Cassandra

Princípios de Otimização no Cassandra

No Apache Cassandra, otimizar a performance de consulta é uma tarefa realizada principalmente durante a fase de **modelagem dos dados**. Como o banco não executa JOINs ou agregações em tempo real de forma eficiente, a regra essencial é: **Uma Tabela para Cada Consulta (One Table Per Query)**.

1. Estratégias de Compacção de SSTables

A Compacção (Compaction) é o processo em segundo plano que combina múltiplas SSTables pequenas numa única SSTable maior, purgando dados sobrescritos ou eliminados.

Estratégias Principais de Compacção:

  • SizeTieredCompactionStrategy (STCS): Padrão. Junta SSTables de tamanhos semelhantes. É ideal para tabelas com alto volume de gravações (Write-Heavy).
  • LeveledCompactionStrategy (LCS): Organiza SSTables em níveis (Levels). Garante que 90% das leituras sejam atendidas lendo apenas 1 SSTable por partição (Read-Heavy).
  • TimeWindowCompactionStrategy (TWCS): Agrupa dados em janelas de tempo fixas. É perfeita para dados de séries temporais (Time-Series / IoT / Logs) configurados com TTL.
-- Exemplo de alteração da estratégia de compacção para séries temporais (TWCS)
ALTER TABLE escola_log.sensores WITH compaction = {
    'class': 'TimeWindowCompactionStrategy',
    'compaction_window_unit': 'DAYS',
    'compaction_window_size': '1'
};

2. O Perigo dos Tombstones (Marcadores de Eliminação)

Como as SSTables são imutáveis, quando um registro é excluído (DELETE) ou expira por TTL, o Cassandra não apaga o arquivo do disco imediatamente. Ele grava um marcador especial chamado Tombstone.

Impacto de Performance: Durante uma consulta de leitura, o Cassandra precisa ler e descartar todos os Tombstones encontrados até localizar dados válidos. Se uma partição tiver milhares de Tombstones, a leitura causará latências altas ou erros de ReadTimeoutException.

Boas Práticas: Evite apagar registros individualmente de forma massiva e mantenha o parâmetro gc_grace_seconds devidamente ajustado.

3. Diretrizes Práticas de Modelagem Eficiente

  • Evite a cláusula ALLOW FILTERING: Crie uma nova tabela cuja Partition Key atenda diretamente ao filtro desejado.
  • Limite o tamanho das Partições: Mantenha partições abaixo de 100MB e com menos de 100.000 linhas por partição.
  • Use Batching com Cuidado: O comando LOGGED BATCH deve ser usado apenas para manter a consistência entre tabelas na mesma partição, não para tentar acelerar inserções em lote de partições variadas.

  2. O que é um Tombstone no Apache Cassandra e de que maneira o acúmulo de Tombstones afeta o tempo de resposta das leituras?

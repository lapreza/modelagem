Semana 22 — Aula 1

Conceitos e Tipos de Bancos de Dados NoSQL

O que é o Movimento NoSQL?

O termo NoSQL (originalmente interpretado como "No SQL" e atualmente consagrado como "Not Only SQL" — Não Apenas SQL) refere-se a uma ampla classe de Sistemas de Gerenciamento de Banco de Dados que diferem dos modelos relacionais tradicionais (RDBMS).

Surgiu no final dos anos 2000 para responder aos desafios da Web 2.0, Big Data e aplicações modernas em nuvem, que exigem manipulação de volumes gigantescos de dados não estruturados, altíssima velocidade de leitura/escrita e escala horizontal dinâmica.

Diferencial Chave: Enquanto o SQL enfatiza a consistência estrita e tabelas com esquemas rígidos (schema-rigid), o NoSQL prioriza flexibilidade de dados (schema-less), alta disponibilidade e escalabilidade distribuída.

Os 4 Modelos Principais de Bancos NoSQL

Ao contrário do modelo relacional (baseado estritamente em tabelas, linhas e colunas), os bancos NoSQL dividem-se em 4 famílias fundamentais segundo a sua estrutura de armazenamento:

Modelo Estrutura Principal Principais Casos de Uso Exemplos de Tecnologias
Documentos Documentos hierárquicos (JSON / BSON / XML). Catálogos de produtos, E-commerce, CMS, Perfis de usuários. MongoDB, CouchDB
Chave-Valor (Key-Value) Pares simples de chave e valor associado. Cache em memória, gerenciamento de sessões, carrinhos de compras. Redis, Amazon DynamoDB
Família de Colunas (Wide-Column) Colunas organizadas dinamicamente em famílias. Análise de Big Data, logs de acesso, séries temporais, IoT. Apache Cassandra, HBase
Grafos (Graph) Nós (entidades) e Arestas (relacionamentos diretos). Redes sociais, motores de recomendação, detecção de fraudes. Neo4j, Amazon Neptune

Motivações para o Uso do NoSQL

  • Esquema Dinâmico (Schema-less): Permite alterar a estrutura dos dados armazenados sem a necessidade de comandos lentos como ALTER TABLE.
  • Escalabilidade Horizontal (Scale-Out): Facilidade para distribuir a carga adicionando servidores populares comuns ao cluster, ao invés de investir em um único servidor gigante e caro (Scale-Up).
  • Desempenho em Alta Carga: Otimização para operações específicas em memória ou disco sem o gargalo de múltiplos JOINs relacionais complexos.

Semana 22 — Aula 2

Comparação entre SQL e NoSQL

Tabela Comparativa Direta: SQL vs. NoSQL

Escolher entre um banco de dados Relacional (SQL) e um Não-Relacional (NoSQL) exige compreender o compromisso entre integridade estrita e flexibilidade de escala.

Característica Bancos de Dados SQL Bancos de Dados NoSQL
Modelo de Dados Tabelas estritas com linhas e colunas. Documentos, Chave-Valor, Colunas ou Grafos.
Esquema (Schema) Rígido e pré-definido (DDL). Flexível/Dinâmico (Schema-less).
Escalabilidade Vertical (Scale-Up: CPU/RAM no mesmo servidor). Horizontal (Scale-Out: distribuição em nós/clusters).
Consistência Garantia estrita ACID. Consistência Eventual / Modelo BASE.
Linguagem de Consulta SQL padronizado (ANSI/ISO). APIs proprietárias, métodos de objetos ou JSON.
Relacionamentos Fortes via PK/FK e JOINs nativos. Desnormalizados (dados embutidos) ou sem JOINs nativos.

ACID vs. BASE

Modelo ACID (Tradicional em SQL)

  • Atomicity: Tudo ou nada.
  • Consistency: Validação total de regras de integridade.
  • Isolation: Transações concorrentes não interferem entre si.
  • Durability: Dados salvos persistem em disco.

Modelo BASE (Predominante em NoSQL)

  • Basically Available: O sistema prioriza responder às requisições, mesmo que parcialmente.
  • Soft-State: O estado dos dados pode mudar ao longo do tempo sem intervenção direta (devido à sincronização assíncrona).
  • Eventual Consistency: Os dados eventualmente serão sincronizados e ficarão idênticos em todos os nós do cluster.

O Teorema CAP (Teorema de Brewer)

Formulado por Eric Brewer, o Teorema CAP estabelece que um sistema de banco de dados distribuído pode garantir, no máximo, **duas** de três propriedades fundamentais simultaneamente:

1. Consistency (Consistência): Todos os nós enxergam exatamente os mesmos dados ao mesmo tempo.

2. Availability (Disponibilidade): Todas as requisições recebem uma resposta de sucesso (sem erros ou travamentos).

3. Partition Tolerance (Tolerância a Partições): O sistema continua a funcionar mesmo que ocorra uma falha de comunicação/rede entre nós.

Como falhas de rede (Partições) são inevitáveis em clusters distribuídos, a escolha real em NoSQL se resume entre **CP** (Consistência + Tolerância a Partições, sacrificando resposta rápida imediata) e **AP** (Disponibilidade + Tolerância a Partições, aceitando que nem todos os nós tenham o dado atualizado no exato milissegundo).

Atividade de Fixação

  1. Qual a diferença principal entre o conceito de Consistência Estrita (ACID) e Consistência Eventual (BASE)?
  2. Explique por que em um sistema distribuído a propriedade Partition Tolerance (P) do Teorema CAP é considerada obrigatória.
  3. Em um sistema de transferência financeira bancária, você recomendaria uma arquitetura focada em CP ou AP? Justifique a sua escolha.

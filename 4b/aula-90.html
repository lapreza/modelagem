Semana 23 — Aula 2

Introdução ao Apache Cassandra

O que é o Apache Cassandra?

O Apache Cassandra é um banco de dados NoSQL distribuído de altíssimo desempenho, pertencente à família de **colunas largas (Wide-Column Store)**. Criado originalmente pelo Facebook para resolver problemas de busca na caixa de entrada de mensagens e tornado código aberto pela Apache Software Foundation em 2008.

Diferencial Principal: O Cassandra foi desenhado para lidar com petabytes de dados espalhados por centenas de servidores comuns, oferecendo alta disponibilidade sem ponto único de falha (Single Point of Failure - SPOF) e escrita de baixíssima latência.

Arquitetura Descentralizada (Ring Architecture)

Diferente do MongoDB (que usa nós primários e secundários), o Cassandra utiliza uma arquitetura **Peer-to-Peer (Par-a-Par)** em formato de anel (Ring Topology):

  • Todos os nós são iguais: Não existe nó "mestre" ou "servidor principal". Qualquer nó no cluster pode receber qualquer requisição de leitura ou escrita.
  • Gossip Protocol: Protocolo interno contínuo em que os nós trocam mensagens de estado entre si para monitorar quem está ativo no cluster.
  • Particionamento por Hash (Partition Key): Uma função hash converte a chave de partição da linha em um número e determina exatamente em qual nó do anel o dado será gravado.

Estrutura de Dados e a Linguagem CQL

Embora seja NoSQL, o Cassandra disponibiliza uma linguagem de consulta declarativa muito semelhante ao SQL tradicional, chamada CQL (Cassandra Query Language).

Conceitos de Organização:

  • Keyspace: O container equivalente a um *Database* no mundo SQL. Define as estratégias de replicação e o fator de cópias no cluster.
  • Table (Coluna Larga): Estrutura composta por linhas e colunas dinâmicas. Cada linha pode ter um número diferente de colunas gravadas em disco.
  • Primary Key: Composta obrigatoriamente por uma Partition Key (define em qual nó o dado mora) e opcionalmente por Clustering Columns (definem a ordenação física dos dados dentro do nó).

Exemplo de DDL em CQL:

-- Criando um Keyspace no Cassandra
CREATE KEYSPACE escola_log WITH replication = {
    'class': 'SimpleStrategy', 
    'replication_factor': 3
};

-- Criando uma tabela para logs de sensores de temperatura
CREATE TABLE escola_log.sensores (
    id_sensor uuid,
    data_leitura timestamp,
    temperatura float,
    PRIMARY KEY (id_sensor, data_leitura)
) WITH CLUSTERING ORDER BY (data_leitura DESC);

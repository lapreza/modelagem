Semana 23 — Aula 3

Introdução ao Redis

O que é o Redis?

O Redis (Remote Dictionary Server) é um armazenador de estrutura de dados em memória (In-Memory Data Store) de código aberto, utilizado principalmente como banco de dados NoSQL do tipo Chave-Valor (Key-Value), sistema de cache de altíssima velocidade e barramento de mensagens (Message Broker / Pub-Sub).

Desempenho Extremo: Por manter todas as suas operações gravadas diretamente na memória RAM, o Redis entrega respostas na casa de sub-milissegundos, processando centenas de milhares de operações por segundo.

Estruturas de Dados Suportadas pelo Redis

Diferente de sistemas simples de chave-valor que aceitam apenas texto bruto, o Redis é conhecido como um **Servidor de Estruturas de Dados**, pois permite associar chaves a diversos tipos complexos:

  • Strings: O tipo básico (texto, inteiros, números binários de até 512MB).
  • Hashes: Mapas de campos e valores dentro de uma chave (ideal para objetos como dados de usuário).
  • Lists: Listas ordenadas de strings que permitem inserções rápidas no início (LPUSH) ou no fim (RPUSH).
  • Sets: Coleções não ordenadas de elementos únicos (sem duplicatas).
  • Sorted Sets (ZSets): Sets onde cada elemento possui um peso/pontuação (score), sendo mantidos sempre ordenados (excelente para placares de jogos e *rankings*).

Exemplos de Comandos Básicos no Redis CLI

# Gravar e ler uma string simples
SET usuario:100:nome "Rafael Lapreza"
GET usuario:100:nome

# Definir uma chave com tempo de expiração (TTL) de 60 segundos
SETEX sessao:token_abc 60 "dados_da_sessao"

# Operações em Hash (Objeto)
HSET usuario:100 email "rafael@email.com" idade "45"
HGETALL usuario:100

# Adicionar elemento em uma Lista (Fila/Fila de Mensagens)
RPUSH fila:tarefas "enviar_email_boas_vindas"
LPOP fila:tarefas

Persistência no Redis

Mesmo sendo um banco em memória, o Redis disponibiliza dois mecanismos para salvar os dados em disco e evitar perdas no caso de reinicialização do servidor:

  • RDB (Redis Database Backup): Tira *snapshots* (retratos compactos em ponto no tempo) da memória em intervalos configuráveis.
  • AOF (Append-Only File): Registra em log cada comando de escrita recebido pelo servidor, permitindo reproduzir a sequência exata de operações na inicialização.

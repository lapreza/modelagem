Semana 24 — Aula 3

Operações no Apache Cassandra

Manipulação de Dados com CQL

No Apache Cassandra, a linguagem CQL (Cassandra Query Language) fornece sintaxe familiar baseada em SQL para executar operações de inserção, leitura, atualização e exclusão. Contudo, devido à sua arquitetura distribuída sem JOINs nativos, as consultas são estritamente condicionadas à composição da **Chave Primária (Primary Key)**.

1. Inserção de Dados (INSERT / TTL)

No Cassandra, o comando INSERT não verifica se a linha já existe antes de escrever (evitando lecturas prévias lentas). Se a Chave Primária já existir, a linha é simplesmente sobrescrita — comportamento conhecido como UPSERT. 

-- Inserindo um registo de log de utilizador
INSERT INTO escola_log.acessos (id_usuario, data_acesso, ip, acao) 
VALUES (a1b2c3d4-0000-0000-0000-000000000001, toTimestamp(now()), '192.168.1.10', 'login');

-- Inserindo dados com expiração automática (TTL em segundos: 86400s = 24h)
INSERT INTO escola_log.acessos (id_usuario, data_acesso, ip, acao) 
VALUES (a1b2c3d4-0000-0000-0000-000000000002, toTimestamp(now()), '192.168.1.11', 'login')
USING TTL 86400;

2. Leitura de Dados (SELECT e Filtros)

As consultas com SELECT devem filtrar obrigatoriamente pela Partition Key para que o cluster saiba em qual nó procurar o dado sem ter de varrer todos os servidores (evitando o FULL SCAN). 

-- Consulta eficiente: filtra pela Partition Key (id_usuario)
SELECT data_acesso, ip, acao 
FROM escola_log.acessos 
WHERE id_usuario = a1b2c3d4-0000-0000-0000-000000000001;

-- Filtrando por intervalo na Clustering Column (data_acesso)
SELECT ip, acao 
FROM escola_log.acessos 
WHERE id_usuario = a1b2c3d4-0000-0000-0000-000000000001 
  AND data_acesso >= '2026-03-01 00:00:00+0000';

Cláusula ALLOW FILTERING: Tentar filtrar por colunas que não pertencem à chave primária exige a adição de ALLOW FILTERING. Contudo, essa prática deve ser evitada em produção pois consome recursos de múltiplos nós no anel.

3. Atualização e Eliminação (UPDATE e DELETE)

Ambas as operações requerem a especificação exata de todos os campos da Primary Key na cláusula WHERE. 

-- Atualizar a ação de um registo específico
UPDATE escola_log.acessos 
SET acao = 'logout' 
WHERE id_usuario = a1b2c3d4-0000-0000-0000-000000000001 
  AND data_acesso = '2026-03-01 10:30:00+0000';

-- Eliminar um registo (Gera internamente um marcador "Tombstone")
DELETE FROM escola_log.acessos 
WHERE id_usuario = a1b2c3d4-0000-0000-0000-000000000001 
  AND data_acesso = '2026-03-01 10:30:00+0000';

  2. Por que é altamente desaconselhado o uso constante da cláusula ALLOW FILTERING em ambientes de produção com grandes volumes de dados?

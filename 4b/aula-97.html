Semana 25 — Aula 1

Replicação de Dados no MongoDB (Replica Sets)

O que é um Replica Set?

Um Replica Set no MongoDB é um grupo de instâncias mongod que mantêm o mesmo conjunto de dados. A replicação garante **alta disponibilidade**, **redundância de dados** e **tolerância a falhas** em ambientes de produção.

Configuração Mínima Recomendada: Um Replica Set de produção deve conter no mínimo 3 nós votantes (por exemplo: 1 Primário e 2 Secundários) para garantir quórum nas eleições automatizadas.

Membros de um Replica Set

1. Nó Primário (Primary)

É o único nó do conjunto que recebe todas as operações de escrita (insert, update, delete). O nó primário regista todas as suas alterações num log especial chamado oplog (Operations Log).

2. Nós Secundários (Secondary)

Replicam o oplog do nó primário e aplicam as operações nos seus próprios conjuntos de dados de forma assíncrona. Podem atender a operações de **leitura** (caso a aplicação utilize a configuração de Read Preference adequada).

3. Nós Árbitros (Arbiter)

Não armazenam dados e não podem tornar-se primários. A sua única função é participar nas **eleições** de um novo nó primário fornecendo um voto de desempate, reduzindo custos de infraestrutura.

Oplog e o Processo de Failover

Quando o nó primário fica indisponível (por falha de hardware ou perda de conexão), os nós secundários realizam uma **eleição automática** para escolher o novo primário. 

// Inicializando um Replica Set via mongosh
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "mongo1.escola.internal:27017" },
    { _id: 1, host: "mongo2.escola.internal:27017" },
    { _id: 2, host: "mongo3.escola.internal:27017" }
  ]
});

// Verificando o estado do cluster de replicação
rs.status();

Read Preference: A aplicação pode decidir onde ler os dados: primary (padrão, garante consistência total), secondary (aumenta o throughput de leitura, aceita consistência eventual) ou primaryPreferred.

Semana 6 — Aula 3

Views (Vistas) e Índices (INDEX)

O que são Views (Vistas)?

Uma View é uma tabela virtual baseada no conjunto de resultados de uma consulta SQL. Ela não armazena os dados fisicamente em disco, mas funciona como uma "janela" ou atalho armazenado para consultas complexas.

Vantagens das Views:

  • Simplificação de Consultas: Esconde a complexidade de múltiplos JOINs e filtros num único nome simples.
  • Segurança e Controle de Acesso: Permite expor apenas determinadas colunas para certos utilizadores (escondendo salários, senhas ou CPFs).
-- Criando uma View que simplifica a listagem de alunos e seus cursos
CREATE VIEW vw_alunos_cursos AS
SELECT aluno.id_aluno, aluno.nome AS aluno_nome, curso.nome_curso
FROM aluno
INNER JOIN curso ON aluno.id_curso = curso.id_curso;

-- Consultando a View como se fosse uma tabela comum
SELECT * FROM vw_alunos_cursos WHERE nome_curso = 'Informática';

O que são Índices (INDEX)?

Um Índice é uma estrutura de dados (geralmente uma Árvore B/B-Tree) criada no SGBD para acelerar a localização e a busca de linhas numa tabela.

Analogia Prática: Funciona como o índice remissivo no final de um livro didático. Em vez de ler o livro inteiro página por página (Table Scan), o leitor vai direto para a página indicada no índice.

Quando criar Índices?

  • Em colunas frequentemente utilizadas na cláusula WHERE.
  • Em colunas utilizadas para fazer junções (ON tabelaA.fk = tabelaB.pk).
  • Em colunas utilizadas na ordenação (ORDER BY).
-- Criando um índice na coluna email da tabela aluno para acelerar buscas de login
CREATE INDEX idx_aluno_email ON aluno(email);

-- Criando um índice composto por dois campos
CREATE INDEX idx_aluno_nome_cpf ON aluno(nome, cpf);

Custo dos Índices: Embora acelerem bastante o SELECT, os índices tornam as operações de INSERT, UPDATE e DELETE ligeiramente mais lentas, pois o índice precisa de ser reorganizado em disco a cada alteração de dados.

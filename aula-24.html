Semana 6 — Aula 4

Transações (TCL) e Controle de Concorrência

O que é uma Transação em Banco de Dados?

Uma Transação é uma sequência de operações SQL executadas como uma única unidade lógica de trabalho. Ou todas as instruções são salvas com sucesso no banco, ou nenhuma delas é aplicada.

Exemplo Clássico (Transferência Bancária): Tirar R$ 100 da Conta A e depositar R$ 100 na Conta B. Se o sistema cair entre a saída e o depósito, o dinheiro não pode sumir; a transação inteira deve ser cancelada.

As Propriedades ACID

Para garantir a confiabilidade em bancos de dados relacionais, cada transação precisa respeitar o conjunto de regras conhecido como ACID:

  • A — Atomidade (All or Nothing): A transação é indivisível. Ou executa 100% dos comandos, ou volta ao estado inicial.
  • C — Consistência: A transação leva o banco de um estado válido para outro estado válido, respeitando todas as regras de integridade (PK, FK, etc.).
  • I — Isolamento: Transações concorrentes executadas simultaneamente por múltiplos usuários não interferem nos dados umas das outras.
  • D — Durabilidade: Após o salvamento, os dados são gravados permanentemente em disco e não serão perdidos mesmo em caso de falha de energia.

Comandos Práticos de Transação (TCL)

Utilizamos três instruções principais para controlar transações:

  • START TRANSACTION (ou BEGIN TRANSACTION) — Marca o início do bloco de transação.
  • COMMIT — Confirma e salva permanentemente todas as alterações feitas desde o início da transação.
  • ROLLBACK — Desfaz e descarta todas as alterações feitas durante a transação, retornando ao estado anterior.
-- Exemplo Prático de Transação com Validação
START TRANSACTION;

-- Débito na conta de origem
UPDATE conta SET saldo = saldo - 100 WHERE id_conta = 1;

-- Crédito na conta de destino
UPDATE conta SET saldo = saldo + 100 WHERE id_conta = 2;

-- Se tudo correu bem, salvamos permanentemente:
COMMIT;

-- Caso ocorra algum erro no processo, desfazemos com:
-- ROLLBACK;

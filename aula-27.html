Otimização de Consultas SQL (Query Tuning)

Por que a Otimização é Crítica?

À medida que uma base de dados cresce de milhares para milhões de registos, consultas mal escritas que demoravam milissegundos passam a demorar minutos, travando a aplicação inteira. A otimização de consultas (Query Tuning) busca reduzir o consumo de CPU, I/O de disco e memória RAM do servidor.

Analisando Planos de Execução com o EXPLAIN

O comando EXPLAIN antecede uma consulta SELECT para mostrar como o otimizador do SGBD pretende buscar os dados. 

-- Analisando o plano de execução de uma busca
EXPLAIN SELECT aluno.nome, curso.nome_curso
FROM aluno
INNER JOIN curso ON aluno.id_curso = curso.id_curso
WHERE aluno.email = 'aluno@escola.sp.gov.br';

Métricas Importantes do EXPLAIN:

  • type: Indica o tipo de junção/busca. Se for ALL, significa que o SGBD está a fazer um Full Table Scan (lendo a tabela inteira linha a linha), o que deve ser evitado! Se for ref ou const, está a usar índices corretamente.
  • rows: Estimativa do número de linhas examinadas.
  • key: Mostra qual índice foi escolhido para a consulta.

Regras de Ouro para Escrever SQL de Alta Performance

1. Evite o uso de SELECT *

Retorne apenas os campos necessários. O SELECT * aumenta o tráfego de rede e impede o uso de índices de cobertura.

2. Cuidado com Coringas no Início da Cláusula LIKE

Buscas como WHERE nome LIKE '%Silva' não conseguem utilizar índices normais B-Tree, forçando a varredura completa da tabela. Prefira LIKE 'Silva%'.

3. Evite Funções em Colunas Dentro da Cláusula WHERE

Consultas como WHERE YEAR(data_cadastro) = 2026 desativam o uso do índice da coluna.
Forma Otimizada: WHERE data_cadastro BETWEEN '2026-01-01' AND '2026-12-31'.

4. Prefira EXISTS a IN em Subqueries Grandes

O operador EXISTS encerra a busca assim que encontra a primeira correspondência, enquanto IN pode carregar listas gigantes na memória.

Atividade Prática

  1. Reescreva a consulta ineficiente SELECT * FROM aluno WHERE UPPER(nome) = 'MARCOS'; de forma a permitir o aproveitamento de um índice na coluna nome.
  2. O que significa a presença do valor ALL na coluna type do resultado do comando EXPLAIN?
  3. Qual o impacto negativo de aplicar uma função matemática numa coluna dentro da cláusula WHERE?
